## Detailed Logic Flow & Conductor Orchestration

This is the exact logical step-by-step sequence when a user triggers the `/auto` flow:

### Phase 1: Initiation and Promo Lock Check
1. **Step 1 (`/auto` - Locked)**:
   - The user sends `/auto`. The Telegram webhook catches the command and sends it to `app.py`.
   - `app.py` routes the text to `handle_intake` in `intake.py`.
   - Before setting the mode or step, `intake.py` checks `can_generate_report(chat_id)`.
   - Because the test user has no promo code yet, the check returns `False`.
   - The bot responds with: `🔑 *Report Locked.* Please enter your promo code to generate your monthly forecast report.`

2. **Step 2 (Promo Code Acceptance)**:
   - The user sends the promo code `frenfren`.
   - `app.py` catches this, matches it against the configured `PROMO_MONTHLY` environment variable, and writes to the DB: `db.set_monthly_code(chat_id, True)`.
   - The bot replies: `✅ *Promo code accepted!* You can now generate your monthly forecast report.`

3. **Step 3 (`/auto` - Unlocked)**:
   - The user sends `/auto` again.
   - `intake.py` passes the `can_generate_report` check successfully because the code was saved in the DB in Step 2.
   - The bot calls `delete_session(chat_id)` to wipe any previous session state.
   - Intake mode is set: `session.metadata["intake_mode"] = "auto"`.
   - Session step is set to `"COLLECTING"`.
   - The bot runs the initial conductor: `reply, session = await run_conductor(session, "__init__")`.
   - Pydantic AI agent `auto_agent` sees all 4 required fields (`alias`, `gender`, `dob`, `location`) are missing and prompts the user conversationally:
     > *"Sure! To compute your Bazi chart, could you please provide your alias, gender (M/F), date of birth (YYYY-MM-DD HH:MM), and your birth location?"*

### Phase 2: Providing Bio Details
1. **Step 4 (Providing Name/Alias & Gender)**:
   - The user sends: `Name: Test Profile, Alias: TEST, Gender: Male`.
   - `intake.py` sees `session.step == "COLLECTING"` and invokes `run_conductor(session, text)`.
   - `auto_agent` parses the text, extracts `alias="TEST"` and `gender="M"`, and writes them to the structured `AutoResult`.
   - `_apply_extracted` commits these details into `session.metadata["intake"]`.
   - `run_conductor` evaluates missing fields. Since `dob` and `location` are still missing, it generates a conversational follow-up:
     > *"Thanks, TEST. Could you please provide your date of birth (YYYY-MM-DD HH:MM) and birth location?"*

### Phase 3: Calculation and Confirmation
1. **Step 5 (Providing DOB & Location)**:
   - The user sends: `DOB: 1977-04-28 11:51, Location: Singapore`.
   - `intake.py` passes the text to `run_conductor(session, text)`.
   - `auto_agent` extracts `dob="1977-04-28 11:51"` and `location="Singapore"`.
   - `_apply_extracted` writes these details to the session metadata.
   - `run_conductor` evaluates `still_missing`. Because all 4 fields are now collected, `still_missing` is empty, so it returns `None, session`.
   - `intake.py` receives `reply is None` and triggers the Bazi calculation engine (`run_calendar_node`) to compute the pillars, sets `session.step = "CONFIRM"`, and returns the playback menu (`_format_playback`) showing the computed pillars:
     > *"📋 Here is what I understood: ... Reply Yes to proceed, or tell me what to fix."*

2. **Step 6 (User Confirmation)**:
   - The user sends `Yes`.
   - `intake.py` transitions `session.step = "TAILORING"` and asks the first customization/tailoring question.

3. **Step 7 (Declining Customization)**:
   - The user sends `No`.
   - The bot notes that tailoring is complete, transitions to `"PROCESSING"`, and adds the report job to the queue.
